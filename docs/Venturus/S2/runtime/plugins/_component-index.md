# Plugin Components Index

Project-specific reusable components that supplement MDS.

| Component | File | CSS | JS | Description |
|-----------|------|-----|----|----|
| **Multi-Select** | [`proj-multi-select.html`](proj-multi-select.html) | [`proj-multi-select.css`](proj-multi-select.css) | [`proj-multi-select.js`](proj-multi-select.js) | Multi-select dropdown with tag display. Supports flat lists and hierarchical (tree) data via mode option. The open list floats above clipping containers, opens upward when there is no room below, and scrolls inside after about 10 rows. |
| **Combobox** | [`proj-combobox.html`](proj-combobox.html) | [`proj-combobox.css`](proj-combobox.css) | [`proj-combobox.js`](proj-combobox.js) | Searchable — and optionally creatable — single-select. **Enhances a native `<select>`**: add `proj-combobox` to it, keep the `<option>`s as the data source, read `select.value`, listen for `change` as usual. `data-combobox-create="true"` adds an "Add «typed value»" row; creating fires `proj-combobox:create` so the page can persist the value into its own option list. No init call — delegated document listeners, so selects rendered later (table rows, modals) just work. Fills the gap between MDS Stylized Select (no search, no create) and `proj-multi-select` (searchable but multi + no create). **Depends on `proj-popover-editor`.** Opens on click in the capture phase with `stopPropagation()` — required, because MDS hides every `.popover` on an outside click and the trigger is a bare `<select>`. |
| **Popover Editor** | [`proj-popover-editor.html`](proj-popover-editor.html) | [`proj-popover-editor.css`](proj-popover-editor.css) | [`proj-popover-editor.js`](proj-popover-editor.js) | Content-agnostic floating editor panel built on MDS popover. Plugin owns wrapper, smart auto-positioning, arrow placement, and dismissal; caller supplies title/body/footer HTML. |
| **Inline Field Error** | [`proj-field-error.html`](proj-field-error.html) | [`proj-field-error.css`](proj-field-error.css) | [`proj-field-error.js`](proj-field-error.js) | The one way to show a validation error under a field. **Callers pass a cause, not a message** — the plugin owns the copy, and there are only seven patterns: `required()` → "Enter <Field Name>" (or "Select <Field Name>" for a `<select>`, checklist or radio group), `invalid()` → "Enter a valid <Field Name>", `duplicate()` → "<Field Name> already in use" (`opts.scope` appends a qualifier), `outOfRange()` → "Enter a number between 5 and 1000" (either bound may be absent), `tooLong()` → "Use 64 characters or fewer", `format()` → "Enter a valid <Field Name> — <plain-language hint>", and `show()` as the raw-message escape hatch. The three constraint-shaped causes degrade to `invalid()` when their parameters are missing, and `format()`'s hint must read as prose — never a raw regular expression. Field name resolves from `opts.label` → `data-error-label` → `<label for>` → the nearest `.setting-row` / `.form-group` label → placeholder, warning to the console if it has to guess. Reuses a message element already in the markup when one matches the `<fieldId>Error` / `<fieldId>-error` convention, otherwise injects a `form-help--error` span; applies MDS `form-input--invalid`, `aria-invalid` and `aria-describedby`, and hides the field's own `.form-help` while an error shows. The CSS styles all three legacy message classes (`.form-help--error`, `.form-error`, `.setting-error`) so prototypes need no local error styling — **do not add any**. Pure utility, no `init()`. Replaced four divergent per-prototype mechanisms across the prototype forms. |
| **Source Toggle** | [`proj-source-toggle.html`](proj-source-toggle.html) | [`proj-source-toggle.css`](proj-source-toggle.css) | [`proj-source-toggle.js`](proj-source-toggle.js) | Pill toggle switching between two data sources (Groundhog / Kodiak). Ported from Atrium `SourceToggle`. Supports active/disabled states per option; emits `proj-source-toggle:change` events. |
| **Cascader** | [`proj-cascader.html`](proj-cascader.html) | [`proj-cascader.css`](proj-cascader.css) | [`proj-cascader.js`](proj-cascader.js) | Multi-column, data-driven drilldown picker. `columns` define the levels and each level's single/multi select mode; `getOptions(level, path)` supplies data on demand. Single last column closes the popup; multi columns stay open. Popup portaled to `<body>`. |
| **Timeline** | [`proj-timeline.html`](proj-timeline.html) | [`proj-timeline.css`](proj-timeline.css) | [`proj-timeline.js`](proj-timeline.js) | Horizontal read-only milestone timeline with progress line. `ProjTimeline.create({ containerId, milestones }).init()`; states (past/current/draft/future) + `selected` ring derived from milestone flags. Built-in template or custom `templateId`. **JS loaded per-prototype via `<script>` tag** (not via `plugins.js`). |
| **Wizard** | [`proj-wizard.html`](proj-wizard.html) | [`proj-wizard.css`](proj-wizard.css) | [`proj-wizard.js`](proj-wizard.js) | Full-screen takeover wizard shell: header (close + title), stepper (built on `proj-timeline`), caller-owned body + footer. `ProjWizard.create({ steps, title }).open()`; `setStep`/`setTitle`/`bodyEl`/`footerEl`/`close`. Escape closes; overlay portaled to `<body>`. **Depends on `proj-timeline`; both JS loaded per-prototype via `<script>` tags (timeline first).** |
| **Requirements Panel** | [`proj-requirements-panel.html`](proj-requirements-panel.html) | [`proj-requirements-panel.css`](proj-requirements-panel.css) | [`proj-requirements-panel.js`](proj-requirements-panel.js) | Read-only viewer for a prototype's `requirements.md` (the formal requirements document). Docked, resizable right-edge panel — no overlay, the whole app shifts left; re-reads the file on every open; Copy button for the raw Markdown. **Self-gating — the ribbon button is only injected when `requirements.md` exists**, and prototypes add no markup. `ProjRequirementsPanel.open/close/toggle()`. Was `assets/canvas/requirements-system.js` until the `.davinci/` migration deleted the whole canvas asset tree it lived in; rebuilt as a plugin so it survives plugin top-ups — **do not move it back under `.davinci/assets/`**. **Owns two things `proj-qa-panel` depends on:** the vendored `marked.min.js` (loaded first by `plugins.js`) and the `.requirements-drawer__markdown` typography. |
| **Q&A Panel** | [`proj-qa-panel.html`](proj-qa-panel.html) | [`proj-qa-panel.css`](proj-qa-panel.css) | [`proj-qa-panel.js`](proj-qa-panel.js) | Read-only viewer for a prototype's `qa.md` (open questions about the design, from its requirements or the gaps in them). Docked, resizable panel mirroring the Requirements drawer; re-reads the file on every open; Copy button for the raw Markdown. **Self-gating — the ribbon button is only injected when `qa.md` exists**, and prototypes add no markup. **Depends on `proj-requirements-panel`** for the `requirements-drawer__markdown` typography and the global `marked` — without it, `qa.md` renders as raw unformatted text. `ProjQaPanel.open/close/toggle()`. |
| **Error Cases Panel** | [`proj-error-cases-panel.html`](proj-error-cases-panel.html) | [`proj-error-cases-panel.css`](proj-error-cases-panel.css) | [`proj-error-cases-panel.js`](proj-error-cases-panel.js) | Read-only viewer for a prototype's `error-cases.md`: the hidden error, blocked and warning states (those needing a specific seeded record or a non-obvious sequence) with the flow to reach each. Docked, resizable panel, same model as the Q&A panel; Copy button. **Self-gating — the ribbon button is only injected when `error-cases.md` exists** (today: manage-infrastructure), prototypes add no markup. **Depends on `proj-requirements-panel`** for the markdown typography. `ProjErrorCasesPanel.open/close/toggle`. |
| **JSON Diff** | [`proj-json-diff.html`](proj-json-diff.html) | [`proj-json-diff.css`](proj-json-diff.css) | [`proj-json-diff.js`](proj-json-diff.js) | Two JSON payloads side by side, aligned line by line: per-pane line numbers, red/green line tints, an inline mark on the part of a paired line that changed, per-pane copy button, and a "N differences found" badge with prev/next. `ProjJsonDiff.create({ containerId, left, right }).render()`; `count` / `next()` / `prev()`. **Has no height and no vertical overflow of its own** — the host provides the scroll container and the pane headers stick to it. **Alignment:** common prefix/suffix trimmed, then anchored on lines that are unique in the WHOLE file (never per-range — in pretty JSON that lets `},` and shared field values anchor structural noise and the diff invents renames), LCS in the gaps, and each pure add/remove run slid to the shallowest-indented boundary it can reach so a coloured block frames the whole record rather than straddling two. |
| **Knowledge Base Launcher** | [`proj-kb-launcher.html`](proj-kb-launcher.html) | [`proj-kb-launcher.css`](proj-kb-launcher.css) | [`proj-kb-launcher.js`](proj-kb-launcher.js) | Owns the Knowledge Base slot in the prototype ribbon. On any prototype it injects an `<a id="kbBtn">` linking into the KB graph page (`prototypes/context/`); on the KB page itself (`body.kb-page`) it injects `<a id="kbBackBtn">` "Back to prototypes" into the same slot instead — never both. The return button's href is the workspace home so middle-click and an empty history still work; its click handler only *prefers* `history.back()`, and only when the referrer is same-origin and is not the KB page (a reload is not a "back"). **Owns no panel** — unlike the Requirements/Q&A drawers it navigates rather than docking, because the KB is ~20 documents with its own search, layouts and reading drawer. Ribbon order slot 0, left of Q&A (1) / Requirements (2) / Change History (3) — slots 1–3 are declared in `proj-requirements-panel.css`, do not renumber. The KB path lives in one place, `KB_URL` in the JS. |
| **Access Gate** | [`proj-access-gate.html`](proj-access-gate.html) | — | [`proj-access-gate.js`](proj-access-gate.js) | Sends an impersonated persona with a `landingPage` field (a prototype folder name, e.g. `manage-devices`) to that prototype on every page load; the landing page itself never redirects. Pair with `disable` rules on `nav.nav-menu .nav-menu__list > .nav-menu__item` so the header stays visible but inert. The user menu is outside `nav.nav-menu`, so persona switching still works. `ProjAccessGate.apply(user)`, called from plugins.js on canvas:ready. |
| **Drawer Lock** | n/a | n/a | [`proj-drawer-lock.js`](proj-drawer-lock.js) | Clicking the backdrop of any `.drawer-overlay` no longer closes the drawer. One capture-phase click listener on `document` that stops the event before MDS and the prototype handlers see it, so every drawer in the workspace is covered with no per-prototype code. Close stays on the X button, the footer buttons and Escape. No `init()`. |
